# v0.0.8 Release Lesson

## 本版目标
增加本地自签名代码签名开发模式，让用户在不加入 Apple Developer Program 的情况下测试 macOS 本地 Xcode 签名流程，同时保留 GitHub 无签名编译与发布。

## 事故 / 风险
本地自签名证书容易被误解为 Apple Developer ID，或被误认为能授予 Network Extension / Packet Tunnel entitlement。

## 根因 / 触发条件
本地代码签名只验证签名链和代码完整性；Apple Team ID、Network Extension entitlement、Provisioning Profile 和 Notarization 是 Apple 授权能力，不会由自签名证书自动获得。

## 修复 / 决策
- 增加 opt-in `local` 构建模式；默认仍为 `unsigned`。
- 使用 macOS Keychain identity 检查本地自签名证书。
- 验证主 APP 与嵌套 App Extension 签名。
- 生成 `LOCAL-SIGNING-REPORT.json`，明确 Apple authorization 为 false。
- GitHub Build / Release / Weekly 不读取本地 Keychain 或用户 P12。
- Release 附加只接受 unsigned APP。
- 源码包拒绝 P12 / PFX / Provisioning Profile 等敏感文件。

## 防回归规则
- 本地私钥永远不进入 Git、源码 ZIP、GitHub Actions Artifact 或 Release。
- 默认构建模式必须为 unsigned；本地签名必须显式选择 `--signing-mode local`。
- 本地签名通过不等于 Apple entitlement 已获授权。
- GitHub Releases 不接受 `local-development-only` 资产。
- 若需要真正 VPN，必须另行取得 Apple 授权并审查 macOS 扩展架构。

## 经验沉淀清单
- 项目经验：将本地开发签名与 GitHub 正式发布签名彻底隔离。
- 安全经验：P12 私钥不得进入版本控制和发布源码包。
- 平台经验：当前上游 macOS Packet Tunnel target 仍是 App Extension；本地自签名不把它变成 System Extension。

## 发布收尾
源码 ZIP 生成后可以交付 Sourcetree；GitHub 云端构建、macOS 本机签名和 VPN 授权均须以真实环境结果为准。

## 验证
Python / Shell / YAML / 项目 / 打包测试按 v0.0.8 Validation Report 记录。当前执行环境不是 macOS，未执行真实 Keychain / Xcode 签名。

## 遗留边界
无 Apple Developer Program 时，不能完成 Developer ID 公证分发，也不能保证 Network Extension / Packet Tunnel VPN 系统授权。
