# Reference Lessons

本模板从长期版本迭代实践中抽象以下跨项目规则：

1. 语法通过不等于行为正确，事务/状态机必须动态测试。
2. 删除前必须证明所有权，未知用户数据保留。
3. 下载永久错误、瞬时错误、内容错误、哈希错误必须分类。
4. 服务解耦不能顺便扩大凭据权限。
5. 版本必须有唯一事实源，generated artifacts 从它重建。
6. CI 不依赖 executable bit 恰好正确；Release 内规范化 mode。
7. root 本地成功不等于 GitHub Runner 成功。
8. README 只是提示，关键规则必须转成脚本/测试/CI。
9. 开发完成、可发布、已归档是不同状态。
10. 发布后必须重新下载线上资产验证。
11. 聊天不是持久状态，中断恢复要靠仓库文件。
12. ChatGPT Web 不应被要求提供看不到的私库远端证据。
13. 私库匿名 404 不是资产不存在的证据。
14. `set -e` 下不要用函数失败码表示“发现更新”等正常状态。
15. 本地缓存命中也必须做身份/哈希/内容校验。
16. 下载先进入 incoming，验证后原子提交。
17. 确定性构建要规范化时间戳、权限、顺序和文件集合。
18. 已发布版本不可覆盖，修复必须新版本。
19. 上一候选版要么真实归档，要么明确未发布 supersede，不能造假。
20. 经验必须进入自动防回归，只写复盘不够。
