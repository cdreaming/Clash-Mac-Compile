# Template Design Decision

## 原方案 1：每轮“项目源码包 + 模板包”

优点是交付清晰；缺点是项目内规则与外部模板容易形成双事实源，长期会出现“项目旧规则”和“模板新规则”谁优先的问题。

## 原方案 2：只携带模板 / 指导文档

优点是模板独立、容易升级；缺点是某一轮漏传、错传模板后，AI 可能失去关键规则。对于 ChatGPT Web + ZIP 交接，这种人工依赖不够稳。

## 采用方案 3：仓库内置治理 + 可导出模板

项目仓库内部保存完整治理能力，因此项目源码 ZIP 就能独立继续开发；每次收尾再额外导出治理模板包，用于跨项目传播。

- 当前项目事实源只有项目仓库。
- `TEMPLATE_VERSION` 管理治理模板版本。
- `build-ai-handoff.py` 自动给出项目包、治理模板包、合并 handoff 包。
- 新项目可从完整模板开始，也可把治理模板合并到旧项目。

它兼容原方案 1/2，但更不容易漂移。
